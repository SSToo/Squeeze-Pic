# 图片格式支持（0.2.2）

压缩图片与格式转换是两个独立工具。压缩保留原格式；转换明确选择目标格式。以下均针对静态、8 位 SDR 图片。

| 格式 | 导入 | 转换导出 | 说明 |
| --- | --- | --- | --- |
| JPEG | 是 | 是 | 有损；已有 JPEG 支持系数域无损优化 |
| PNG | 是 | 是 | 无损编码，支持透明 |
| WebP | 是 | 是 | 有损或严格无损，支持透明 |
| AVIF | macOS | macOS | Rust ravif 编码，macOS ImageIO 解码；当前有损 |
| JPEG XL | 是 | 是 | libjxl 编码，jxl-oxide 解码；sRGB 图片支持逐像素无损校验 |
| HEIF / HEIC | macOS | macOS | Rust 调用 ImageIO；有损，透明区域合成背景色 |
| GIF | 是 | 是 | 当前仅单帧；最多 256 色及二值透明 |
| TIFF | 是 | 是 | 单页、8 位；无损 Deflate，深度策略比较预测方式 |
| BMP | 是 | 是 | 适合兼容需求，不保证文件变小 |
| ICO | 是 | 是 | 最长边不超过 256，等比缩放并透明补齐正方形 |
| ICNS | 是 | 是 | 选取标准图标尺寸，最多 1024；导入读取最大可解码图标 |
| SVG | 是 | 否 | resvg 光栅化后转换为位图；外部图片必须先嵌入 |

JPEG、PNG、WebP 沿用已实现的 ICC / EXIF / XMP 保留路径。新增编码器暂不保留拍摄元数据；HEIF / AVIF / JPEG XL 导入会按 sRGB 读取。严格无损不适用于系统解码的 HEIF / AVIF、非 sRGB JPEG XL，或不能保留 ICC 的输出路径。处理报告显示适用的说明。

PNG、WebP、JPEG XL 的“严格无损”逐像素检查包含透明像素中的隐藏 RGB。转换为图标时会改变画布或尺寸，因此不提供严格无损选项。

0.2.1 的 PNG 优化可使用调色板或较低存储位深，前提是展开后的 8 位像素值完全一致。例如 16 级灰度可用 4 位等价存储；这不会量化颜色，也不会开放 16 位输入的静默降位。

多尺寸 ICO / ICNS 导入转换使用最大图像；同格式压缩暂时拒绝多尺寸图标，避免丢失其余尺寸。

动画 GIF / WebP / APNG / JPEG XL、HDR、16 位和多页 TIFF 会明确拒绝。SVG 导出需要独立的矢量处理设计；普通位图转换不会被标为矢量化。

本机覆盖了全部上述导出格式的编码、解码及尺寸回测。Windows 与 Intel macOS 安装验证仍待完成。
